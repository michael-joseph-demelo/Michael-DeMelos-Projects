## Assistant

## Summary
Pressing both punch buttons at nearly the same time launches both fists in a straight, parallel line. If either fist touches an enemy, the fists drag the enemy back and hold it between them. A dot then travels out to a new `throw_distance` and comes back. Pressing a punch button during that window throws the enemy to the dot and damages it. If the dot gets back to the player first, the enemy escapes.

The approach: `CharacterBase` gets a small grab state machine. `FistBase` gets a "grab punch" mode (straight path, no damage, sends a signal on contact) and a "held" mode where the character controls the fist's position. Enemies get a `set_grabbed()` method. The hold position and the dot sit under `FistSlots`, which already rotates toward the cursor every frame, so aiming the throw works without extra code.

## Suggested changes

**1. Editor: add grab markers and the dot to `characters/CharacterBase.tscn`**
Under `FistSlots`, add a `Node2D` called `GrabSlots` with these children:
- `LGrabSlot` (Marker2D) at `(10, 18)`
- `RGrabSlot` (Marker2D) at `(-10, 18)`
- `HoldPoint` (Marker2D) at `(0, 18)`
- `ThrowDot` (Node2D) at `(0, 18)`: `visible = false`, `z_index = 100`, with a child `ColorRect` of size 3×3 at offset (-1.5, -1.5) in a bright colour

"Left" is +x, matching `LFistSlot`/`LBlockSlot`. Local +Y is the facing direction because `update_fists_rotation()` sets `fist_slots.rotation = angle - 90°`. This follows the same idea as `BlockSlots` used by the shield. Check the spacing in `RobotMan.tscn`: the dummy's collision box is 14 px wide (`NuggetDummy.tscn`), so ±10–11 px keeps it visually between the fists.

**3. `fists/FistBase.gd`: new state, signal and a shared detach helper**
```gdscript
signal grab_connected(fist: FistBase, body: Node)
var is_grab_punch := false
var is_grab_held := false
var grab_speed := 150.0
```
Move the detach block out of `punch()` (everything from `original_slot_parent = ...` to `global_position = punch_origin`) into `_detach_from_slot(origin_dir: Vector2)`. Then `punch()` and the new `grab_punch()` share it:
```gdscript
func grab_punch(direction: Vector2, speed: float) -> void:
    if punching or retracting or is_disabled or is_grab_held:
        return
    grab_speed = speed
    is_grab_punch = true
    _detach_from_slot(direction)   # sets punch_origin, initial/current_direction, reparents to root
    punching = true
    hitbox.set_deferred("monitoring", true)
    update_visual_state()
```
`grab_punch()` doesn't go through `punch()`, so `ThumbsUpFist.punch()` (synergy boost) isn't triggered by a grab.

**4. `FistBase._physics_process()`: straight path**
```gdscript
if punching:
    if is_grab_punch:
        _process_grab_punch(delta)
    elif arc_strength > 0.0: ...

func _process_grab_punch(delta: float) -> void:
    global_position += initial_direction * grab_speed * delta
    slot_node.global_position = global_position   # keeps the chain attached
    rotation = initial_direction.angle() - PI / 2
    traveled_distance = punch_origin.distance_to(global_position)
    if traveled_distance >= max_distance:
        _start_retraction()   # whiff
```
There's no cursor steering and no spin. Also add `if is_grab_held: return` at the top of `_physics_process()` so the character has full control of a held fist.

**5. `FistBase._on_hitbox_body_entered()`: grab instead of damage**
After the `"Shields"` block and the `target_group` check, before `take_damage`:
```gdscript
if is_grab_punch:
    grab_connected.emit(self, body)

```

**6. `FistBase`: hold / release helpers and guards**
```gdscript
func enter_grab_hold() -> void:
    punching = false; retracting = false; is_retract_paused = false
    is_grab_punch = false; is_grab_held = true
    hitbox.set_deferred("monitoring", false)
    sprite.rotation = 0

func exit_grab_hold() -> void:
    is_grab_held = false
    _start_retraction()   # reuse the normal return-to-slot + _reset_fist()
```
In `_start_retraction()` add `if is_grab_held: return` as the first line, and set `is_grab_punch = false`. In `_reset_fist()` set `is_grab_punch = false` and `is_grab_held = false`. The guard matters because `start_retraction_with_delay()` and the damage path both use `call_deferred("_start_retraction")`, which can run after a fist has already been taken over by the grab (see Risks).

**7. `CharacterBase.gd`: state and wiring**
```gdscript
enum GrabState { NONE, REACHING, PULLING, HOLDING, THROWING }
var grab_state := GrabState.NONE
var grabbed_enemy: Node2D = null
var throw_dot_distance := 0.0
var throw_dot_dir := 1.0
var pending_punch := ""       # "left" / "right"
var pending_punch_timer := 0.0

@onready var grab_l: Node2D = $FistSlots/GrabSlots/LGrabSlot
@onready var grab_r: Node2D = $FistSlots/GrabSlots/RGrabSlot
@onready var hold_point: Node2D = $FistSlots/GrabSlots/HoldPoint
@onready var throw_dot: Node2D = $FistSlots/GrabSlots/ThrowDot

func is_grabbing() -> bool: return grab_state != GrabState.NONE
```
In `load_fists()`, connect both fists: `left_fist.grab_connected.connect(_on_grab_connected)` (same for the right fist).

**8. `CharacterBase.handle_fist_inputs()`: detect a two-button press and throw**
The Input Map has no grab action, and pressing two mouse buttons on the exact same frame is unreliable. So hold the first press for `grab_input_window` seconds and fire it as a normal punch only if the other button doesn't follow:
```gdscript
func handle_fist_inputs():
    if is_shielding: return
    var l := Input.is_action_just_pressed("punch_left") and left_fist != null
    var r := Input.is_action_just_pressed("punch_right") and right_fist != null

    if grab_state == GrabState.HOLDING:
        if l or r: throw_grabbed_enemy()
        return
    if is_grabbing(): return

    if (l and r) or (pending_punch == "left" and r) or (pending_punch == "right" and l):
        pending_punch = ""
        try_start_grab()
        return
    if pending_punch == "":
        if l: pending_punch = "left"; pending_punch_timer = grab_input_window
        elif r: pending_punch = "right"; pending_punch_timer = grab_input_window
    else:
        pending_punch_timer -= get_process_delta_time()
        if pending_punch_timer <= 0.0:
            var f := left_fist if pending_punch == "left" else right_fist
            f.punch(get_global_mouse_position())
            pending_punch = ""
```
`try_start_grab()`: if either fist is `punching`, `retracting`, `is_disabled` or `is_grab_held`, fall back to a normal punch on the free fist. Otherwise:
```gdscript
var dir := (get_global_mouse_position() - global_position).normalized()
left_fist.grab_punch(dir, grab_reach_speed)
right_fist.grab_punch(dir, grab_reach_speed)
grab_state = GrabState.REACHING
input_vector = Vector2.ZERO
velocity = Vector2.ZERO
```
Both fists use the same `dir` (character → cursor), so they fly in parallel rather than meeting at the cursor.

**9. `CharacterBase._on_grab_connected(fist, body)`**
```gdscript
if grab_state != GrabState.REACHING or not body.has_method("set_grabbed"): return
grabbed_enemy = body
body.set_grabbed(true)
left_fist.enter_grab_hold()
right_fist.enter_grab_hold()

```
Only the first contact counts. The other fist's hit is ignored by the state check.

**10. `CharacterBase._physics_process()`: run the grab**
At the top, after the `is_frozen` check:
```gdscript
if is_grabbing():
    velocity = Vector2.ZERO
    _process_grab(delta)
    move_and_slide()
    update_animation()
    return
```
This skips `handle_movement_input()`, so it also blocks walking, dashing and the shield dash-cancel.
```gdscript
func _process_grab(delta):
    if grabbed_enemy and not is_instance_valid(grabbed_enemy):
        _end_grab(false); return
    match grab_state:
        GrabState.REACHING:
            if not (left_fist.punching or left_fist.retracting or right_fist.punching or right_fist.retracting):
                grab_state = GrabState.NONE   # whiffed
        GrabState.PULLING:
            var done := _move_fist_toward(left_fist, grab_l.global_position, grab_pull_speed * delta)
            done = _move_fist_toward(right_fist, grab_r.global_position, grab_pull_speed * delta) and done
            grabbed_enemy.global_position = (left_fist.global_position + right_fist.global_position) * 0.5
            if done:
                grab_state = GrabState.HOLDING
                throw_dot_distance = hold_point.position.y
                throw_dot_dir = 1.0
                throw_dot.visible = true
        GrabState.HOLDING:
            _snap_fist(left_fist, grab_l.global_position)
            _snap_fist(right_fist, grab_r.global_position)
            grabbed_enemy.global_position = hold_point.global_position
            throw_dot_distance += throw_dot_speed * throw_dot_dir * delta
            if throw_dot_distance >= throw_distance:
                throw_dot_distance = throw_distance; throw_dot_dir = -1.0
            throw_dot.position = Vector2(0, throw_dot_distance)
            if throw_dot_dir < 0 and throw_dot_distance <= 0.0:
                _end_grab(false)   # enemy escapes
```
`_move_fist_toward` / `_snap_fist` set `fist.global_position`, set `fist.slot_node.global_position` to match (same pattern as `FistBase`, so `ChainDrawer` follows), and set `fist.rotation = fist_slots.rotation`. `update_fists_rotation()` still runs in `_process`, which is why aiming works.

**11. `CharacterBase.throw_grabbed_enemy()` and `_end_grab()`**
```gdscript
func throw_grabbed_enemy():
    grab_state = GrabState.THROWING
    throw_dot.visible = false
    var target := throw_dot.global_position
    left_fist.exit_grab_hold(); right_fist.exit_grab_hold()
    var tween := create_tween()
    tween.tween_property(grabbed_enemy, "global_position", target, throw_flight_time) \
        .set_trans(Tween.TRANS_SINE).set_ease(Tween.EASE_OUT)
    await tween.finished
    if is_instance_valid(grabbed_enemy):
        var enemy := grabbed_enemy
        enemy.set_grabbed(false)          # before take_damage: it may queue_free
        enemy.take_damage(throw_damage)
        left_fist._spawn_damage_number(target, throw_damage)
    grabbed_enemy = null
    grab_state = GrabState.NONE

func _end_grab(_thrown: bool):
    throw_dot.visible = false
    if left_fist.is_grab_held: left_fist.exit_grab_hold()
    if right_fist.is_grab_held: right_fist.exit_grab_hold()
    if is_instance_valid(grabbed_enemy): grabbed_enemy.set_grabbed(false)
    grabbed_enemy = null
    grab_state = GrabState.NONE
```
`create_tween()` is bound to the player node, so it stops if the player is freed.

## Risks
- **Deferred retraction runs after the grab takes over a fist (High).** `start_retraction_with_delay()` (fist clash or shield) and the hit path both use `call_deferred("_start_retraction")`. If one grab fist clashes with the dummy's fist on the same frame the other fist connects, the deferred call sets `retracting = true` on a held fist and it flies home mid-hold. Fix: the `if is_grab_held: return` guard in `_start_retraction()` (step 6).
- **Every single punch is delayed (Medium, affects feel).** The input window in step 8 holds each lone punch for `grab_input_window` seconds. At 0.06 s that's about 4 frames. Alternatives: a dedicated `grab` action in the Input Map, or "upgrade" the first fist mid-flight. Tune the window by playtesting.
- **Conflict with the ThumbsUp synergy (Medium, design).** In `ThumbsUpFist.punch()`, the boost only triggers when the second fist is punched while the first is still out. Fast double-taps that used to trigger it will now start a grab instead. Keep the window short, or decide whether ThumbsUp fists can grab.
- **Enemy pushes against the player while held (Medium).** Both are on collision layer 1 with mask 1 (`game.tscn`, `NuggetDummy.tscn`), and the hold point is only ~18 px in front. The player still calls `move_and_slide()`, which can resolve the overlap by nudging the player. Fix: disable the dummy's collision shape in `set_grabbed(true)` (step 13).
- **Overlap when the enemy is released (Low–Medium).** On escape the enemy is released at the hold point, and its collision turns back on while possibly overlapping the player, causing a small push. Consider nudging it out to `hold_point` + a few px, or re-enabling collision a frame later.
- **Enemy dies or is freed mid-grab (Medium).** `take_damage()` calls `queue_free()` at 0 HP, and the throw tween awaits on a node reference. Use `is_instance_valid()` checks (steps 10–11), and call `set_grabbed(false)` before `take_damage()`.
- **Hitpause during the grab (Low).** Both `take_damage()` functions set `get_tree().paused = true` for 0.05 s. The grab logic is in `_physics_process` and pauses cleanly, but a hit from the dummy's in-flight fist during a grab will briefly freeze the dot. That's expected.
- **The dummy's fist already in flight can still hit the player (Low).** `set_grabbed` stops the timer, not a punch already travelling. Accept it, or have the dummy force its fist to retract.
- **Using `is_frozen` for the lock would break aiming (High if done wrong).** `_process` and `update_fists_rotation()` return early when `is_frozen` is set. Use the new `grab_state` instead, as this plan does.
- **Grab fists still interact like normal punches (Low, design).** Grab fists keep `punching = true` while reaching, so `_on_hitbox_area_entered` clashes and the shield block in `_on_hitbox_body_entered` still apply. A shield will stop a grab, the opposite of most fighting games. Only the player has a shield right now, so this doesn't matter yet.
- **Stale walk animation (Low).** `update_animation()` uses `input_vector`, which keeps its last value. Clear it when the grab starts (step 8).
- **Fist disabled mid-grab (Low).** A stamina loss (clash or shield block) can call `disable_fist()` during a grab. Positions are still driven by the grab, so it works, but the fist looks greyed out. Optionally cancel the grab if either fist becomes disabled.
- **Balance (Medium).** `throw_damage` 100 is twice a Standard punch (50). The throw also guarantees a hit after a ~2.5 s window. Tune `throw_damage` and `throw_dot_speed`.

## Test checklist
- Tap left or right click on its own: a normal punch still fires, only slightly delayed. Bezier fists (Boomerang, Banana) still curve.
- Click both buttons together (within the window): both fists fly straight and in parallel, ignoring cursor movement, and the chains follow them.
- Grab into empty space: both fists retract normally at `max_distance` and the player can move again.
- Grab the NuggetDummy: no damage number appears on contact, the dummy is pulled in between the fists, and its punch timer stops.
- While holding: WASD does nothing, E (dash) does nothing, the shield key does nothing, and moving the mouse swings the dummy, fists and dot around the player.
- The dot starts just in front, travels out ~200 px, comes back, and the dummy escapes at the player. After that the dummy punches again within 2–5 s.
- Click during the hold: the dummy flies to the dot, takes `throw_damage`, shows a damage number and flashes white. The fists return and the player can move.
- Throw the dummy until it dies: no errors from freed instances.
- Grab while one fist is disabled (drain stamina by blocking): falls back to a single punch, no grab.
- Grab right as the dummy punches (fists clash): no fist gets stuck flying home while held.
- Shield and the dash-cancel out of shield still work after a grab.
- Swap `game.tscn` fists to ThumbsUp: grabs work, and staggered presses still give the synergy boost.

## Open questions
1. **How is a grab input detected?** Default: both punch buttons within 0.06 s, which adds that much delay to single punches. Alternatives: a dedicated `grab` action in `project.godot`, or upgrading a fist already in flight.
2. **Is the player locked while reaching, or only once holding?** Default: locked from the moment the grab starts until the throw lands or the enemy escapes.
3. **Can the grabbed enemy attack?** Default: no. The punch timer is paused, but the fist can still turn to face the player.
4. **Where does the dot start and end?** Default: it starts at the hold point (~18 px in front) and the enemy escapes when the dot reaches distance 0 (player centre).
5. **Throw damage, flight time and dot speed?** Default: 100 damage, 0.3 s flight, 150 px/s dot speed (about 2.5 s total window), all in `CharacterStats.json`.
6. **Should `throw_distance` be per character or per fist?** Default: per character in `CharacterStats.json`, set to 200 to match `FistBase.max_distance`. That value isn't in `FistStats.json`, so every fist currently uses 200.
7. **Reach speed: shared or per fist?** Default: a shared `grab_reach_speed` so both fists stay together. Fist `move_speed` values range from 80 (Thumbs Up) to 200 (Banana).
8. **Should grabs beat shields?** Default: no, the existing shield code blocks them like punches. Only the player has a shield right now.
9. **Does the throw cost stamina, or do hits on a held enemy do anything?** Default: no stamina cost, and the held enemy can't be hit (its collision is off).
